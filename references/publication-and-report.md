# 报告结构

实现：`reporting/report.py`、`control/orchestration.py`。

## 单条消息结构

1. 标题：证券、市场、知识截止、新闻观察窗、数据版本、策略版本、运行 ID。
2. 宏观背景：截止时已公开的宏观读数。
3. 新闻与事件：综合判断、逐事件贡献、工作流覆盖率、已核实事件、待核实清单。
4. 综合摘要。
5. 限制与复现：数据缺口、运行 ID、代码版本、策略哈希、降级阶段。

## 宏观背景

| 读数 | 默认序列 | 口径 |
|---|---|---|
| 10年−2年国债利差 | DGS10、DGS2 | 最新可知值之差，百分点 |
| CPI 同比 | CPIAUCSL | 最新值相对约一年前的变化，% |
| 汇率变化 | DEXUSEU | 最近 21 个观测的对数变化 |
| 政策利率变化 | DFEDTARU | 最近 21 个观测的差，百分点 |

- 只使用 `available_at` 不晚于知识截止的观测；没有公开时点的观测不计入。
- 同一统计期有多个 vintage 时取截止前最新公开的一个，不用后来的修订值。
- 缺失写原因（`no_data`、`window_insufficient`、`nonpositive_base`），不填 0。
- 读数只作背景描述，不推导个股方向。

## 新闻部分

综合判断行给出利多、利空或中性/多空抵消，以及利多贡献、利空贡献和净贡献；随后是按贡献绝对值排序的事件表（最多 20 行）。计算规则见[新闻证据与七档](news-evidence-and-grades.md)。

每条已核实事件：

- 等级：极大利好/高度利好/中度利好/中性/中度利空/高度利空/极大利空。
- 标题、来源、发布时间、证据范围、方法、链接。
- 依据、事实摘要、核实来源与发布日期、待确认条件、影响强度依据。

未形成已核实评估的发现记录只列为“待核实”（最多 5 条）并说明缺口，不计作利多或利空。展示条数限制不限制综合计算。

## 综合摘要

可以说明：

- 已核实新闻的综合判断、净贡献和事件数。
- 仅有未核实标题，或观察窗内没有合格证据。

不可以：

- 把新闻等级或净贡献换算成概率。
- 把缺少证据写成中性。
- 输出价格预测、买卖、仓位、目标价或图表。

## 降级场景

| 场景 | 仍可交付 | 必须限制 |
|---|---|---|
| 新闻只有标题 | 事件发现、来源、缺口 | 方向结论、正文已核实声称 |
| 工作流未完成 | 已核实部分的综合判断与覆盖率 | 把待处理项当作中性 |
| 无宏观数据或缺公开时点 | 新闻解读 | 宏观背景读数 |
| 证券不在主表 | 以默认身份继续 | 代码变更与退市范围已验证的声称 |
| 网络失败只有旧存档 | 带日期的存档重放 | 最新联网采集声称 |
| 港股公告无许可材料 | 市场新闻与缺口说明 | HKEXnews 自动采集 |

## 复现

每次运行保存：

- 请求、策略版本/哈希、代码版本、知识截止。
- 数据集版本、缺失数据集、阶段状态、限制。
- 新闻影响参数哈希与工作流覆盖。
- Markdown 和 JSON 输出路径。

`reproduce --run-id` 读取冻结清单并重放 Markdown，不用最新数据覆盖。

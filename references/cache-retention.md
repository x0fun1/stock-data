# 七天运行缓存清理

每次 CLI 运行，以及直接调用报告、工作流准备、证据采集和审核导入的主要 Python 入口时，先执行清理。以本次请求开始的 UTC 时间减去 7×24 小时为边界；文件最后写入时间**严格早于**该边界才过期，恰好七天仍保留。新闻发布时间和报告 `--cutoff` 不用于缓存过期判定。读取缓存不刷新其保存期限。

## 清理范围

- `raw/`：下载的原始响应与对应 manifest 成组处理，按这一组最后写入时间判断；近期重新取得的相同响应仍保留。
- `curated/`：已过期的数据快照文件，包含导入或审核后保存在运行目录内的副本；删除后从 SQLite 登记中移除对应版本。
- `reports/`：同一报告的 Markdown、JSON 成组清理；同时移除运行登记。
- `news-workflows/`：整组最后写入超过七天的工作流、采集批次和插件批次；工作流仍活跃时也会清掉其中已过期的旧 collection。删除工作流后，清除失效的 `*-latest.json` 指针。
- `cache/`、`tmp/`、`temp/`、`acceptance/`：过期缓存、临时文件与本地验收输出。
- 运行根目录中可识别的标题导出、摘要、测速结果、安装验证回执及日志。

逻辑上必须一起使用的文件按组内最后写入时间保留，避免删除近期工作流仍使用的任务清单或把报告只删一半。用户原始输入、源码、配置、凭证和 `.venv` 不在清理范围；仅清理运行目录中的生成文件或缓存副本，不跟随符号链接。

在 Skill 自带 `runtime/` 下创建的多个分析子目录会一起检查；外部 `--root` 则只管理该指定目录及其运行子目录。清理与分析共用进程锁，同一运行范围内的新请求等待正在使用缓存的操作完成，标题内部的 32 并发不受影响。常驻 Search/Fetch 服务只在启动时检查一次，不占用分析锁。

超过保存期限后，旧报告、快照和证据可能已不存在，需要重新获取数据、准备 workflow 和采集。七天内仍支持断点续跑与 `reproduce`。collection 内的 `cleanup_enabled=false` / `cleanup_performed=false` 描述批次执行期间不清除证据；独立的运行前七天清理由运行目录下的记录反映。

## 手动检查或立即清理

```bash
# 预览，不删除文件或修改数据库登记
python scripts/skill.py cleanup --root MY-DATA --dry-run

# 按同一七天规则立即清理
python scripts/skill.py cleanup --root MY-DATA
```

清理回执包含开始时间、过期边界、删除文件数、释放字节数、移除的索引数量与失败原因，只覆盖保存一份 `.retention-last.json`，不产生回收副本或不断追加的日志。文件无法删除或数据库无法整理时保留错误记录，不将失败报告为成功。报告的运行 manifest 也包含这次请求的清理摘要。

# 预训练模型与逐日揭示基准

小时扩展已另外完成全部2,764个目标、每次使用全部既往有效历史的研究实验，见[全量小时模型测试](FULL_HOURLY_MODEL_TEST_2026-11.md)。本文的180根日线窗口和185次日频回放仍是原版规格，不能套用于新小时实验。

日期：2026-11-07。首个原型使用 NVDA 日频旧数据，不表示已建立可靠投资概率。

## 本次实际规格

- 复用 Kronos-mini 和匹配 tokenizer 的首次公开权重，模型权重保持冻结。
- 使用 365 根交易日日线，2025-05-27 至 2026-11-05；前 180 根是初始上下文。
- 第 181 根开始逐日预测，一共 185 次。预测器每次只接收最近 180 根已经揭示的实际行情。
- 先将预测、所有生成路径、输入哈希、模型及种子封存，再揭示下一根行情、计分、更新候选状态。
- 全部日期都记录，无论方向预测对错；不删除失败，不改写旧预测。

365 个自然日与 365 根交易日不同。数据行数不得代替交易日历核验。

## 三个比较对象

1. 朴素基准：过去 180 根的开盘到收盘上涨率，采用固定 Laplace 平滑；收盘价基准为上一日收盘。
2. 固定 Kronos：16 个独立生成路径，`sample_count=1` 的 batch 保留原始路径；采样温度 1、top-p 0.9，固定随机种子规则。
3. 每日更新候选：基准与 Kronos 的组合。预测之后根据刚揭示标签的 Brier 损失更新权重；时间衰减 0.99、学习率参数 1.0，规则在实验前固定。

第三项更新的是组合权重，未微调 Kronos 网络。每天追加上下文也不是训练。真正微调预训练网络应另登记实验，不自动每天重训。

## 目标与评分

主目标是下一交易日开盘到收盘的报价方向，辅助目标是下一日收盘报价。它们与收盘到收盘方向分开。单日行动权益不能凭缺记录假定不存在；正式总收益发布仍须服从原公司行动政策。

方向分数评估 Brier、log loss、方向准确率；价格评估 MAE，并与上一收盘基准比较。只有方向准确率提高不代表概率校准、收益改善或风险降低。

生成路径上涨占比属于模型生成分数；未经独立校准、样本外验证不得称为已验证的投资概率。不能把独立采样的 NVDA/SPY 路径随机配对，冒充具有联合结构的跑赢概率。

## 时间分区

| 交易日序号 | 用途 | 边界 |
|---|---|---|
| 1–180 | 初始上下文 | 不包含第 181 日行情 |
| 181–245 | 开发回放，65 次 | 后续研究仅在此比较有限候选 |
| 246–275 | 校准观察，30 次 | 本次不拟合或宣称通过独立概率校准 |
| 276–365 | 固定规则评估，90 次 | 不看效果后改窗口、采样、权重规则 |

可以在最后区间运行预先固定的在线更新算法：每次计分后只能使用已成熟标签；冻结的是算法及超参数，状态按固定规则变化。根据最后区间的表现再手工修改规则，必须把该区间重新标为开发数据，下一版本在新的留出日期评估。

90 个评估日期不足以满足现有 200 样本发布门槛。重复回放同一批数据不会增加独立证据。优化可能无效，不能承诺最终逐日准确。

## 预训练数据与来源限制

模型、tokenizer 权重与 2025-07-01 首次公开版本一致，已核验 SHA-256。本实验第一个预测标签是 2026-02-12，在这些权重公开之后。论文披露的训练截止与具体 mini checkpoint 的逐版本绑定仍有局限，详见运行目录的 checkpoint 审计。

实验使用今天取得的厂商历史报价。历史修订与首次可得版本未完全重建；因此本次标为历史研究回放，不直接晋升为已验证概率模型。下个版本的规则一旦参考本次评估结果，新的验证必须使用新的留出日期或真实前向积累。

## 后续持续改进

用户于2026-11-07提出最低方向准确率60%。后续方向模型将此记录为验收要求：按预先定义的全部评估日期计算，至少60%；同时保留置信区间、涨跌分类、校准和相对朴素基准的证据。不能仅因一次小样本达到60%就晋升，不根据结果删除失败日期。若以后研究只在部分日期发布判断，必须预登记选择规则并同时报告覆盖率，不能与全日期命中率混用。

下一轮预训练候选为 Kronos-small/base、Chronos-2、TimesFM-2.5、Moirai-2.0；FinCast作为额外待核验候选。现有逻辑回归以及CatBoost/LightGBM训练模型也应作为对照。它们尚未在本次NVDA口径实测，不能事先声称比Kronos-mini更好。每个具体checkpoint先锁定权重、源码、发布日期和用途，再登记有限候选预算。

已看过的365日回放和最后90日结果可用于研发比较；基于这些结果选择新模型后，新的确认评估需另留未用于选择的日期，不把重复回放当新证据。

保持固定基准，优化版本单独保存模型及状态；每次升级记录输入、标签截止、配置和比较理由。候选在后续相同日期与基准共同预测，获得足够、稳定的增益及校准证据后才晋升。

正式日常接线应分为 `predict` 与 `reveal/score/update` 两步：预测步骤不读取未成熟标签；揭示步骤核验原预测哈希，评分后更新下一版本。这里的首个脚本完成历史回放和版本证据，尚未创建自动日常采集或调度任务。

小时版沿用相同顺序，但须先取得完整小时库，固定美股常规时段、最后半小时、隔夜和节假日处理。不能把更多相关小时行当作更多独立日期。初版先验证日频一日目标，再扩展小时与 5/20/60 日目标。

## 运行与产物

脚本：`stock-data/scripts/rolling_baseline.py`。

```powershell
python stock-data/scripts/rolling_baseline.py --prices runtime/walk-forward-baseline/NVDA-raw-prices.csv
```

依赖、固定权重和第三方源码保留在被忽略的 `runtime/walk-forward-baseline/`，不改变系统 Python。`protocol.json` 在推理前保存；`forecasts/` 和 `scored/` 分别保留预测与揭示结果；重复执行验证已存预测与状态的一致性。
